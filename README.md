# Effect Worker Monorepo

A production-ready monorepo for building Cloudflare Workers with Effect-TS, featuring shared domain models, type-safe API contracts, and database integration.

## Quick Start

Use Bun 1.4.5, pinned in `package.json`. Wrangler and the Cloudflare dev
servers require a supported Node.js installation.

```bash
bun install    # Install dependencies
bun run build  # Build packages and apps
bun run check  # Type check
bun test       # Run tests with Docker running

# Local development
cd apps/api
bun run dev    # Start dev server
```

## Packages

All packages use the `@repo/*` namespace for internal monorepo imports.

### `@repo/domain`
Core domain schemas and errors (Effect Schema).

```typescript
import { CreateUserSchema, UserNotFoundError } from "@repo/domain"

// Schemas provide both compile-time types and runtime validation.
type CreateUser = typeof CreateUserSchema.Type
```

### `@repo/contracts`
API definitions for HTTP and RPC endpoints. Defines the contract between client and server.

```typescript
import { WorkerApi, UsersGroup, UsersRpc } from "@repo/contracts"
```

**HTTP Groups:**
- `HealthGroup` - Health check endpoints
- `UsersGroup` - User CRUD operations

**RPC Procedures:**
- `UsersRpc` - User operations via RPC

### `@repo/cloudflare`
The Effect Worker adapter and typed Cloudflare binding wrappers.
`Worker.make` owns the isolate and request scopes. `makeCloudflare` uses
the `Env` generated by `wrangler types`.

```typescript
import { makeCloudflare } from "@repo/cloudflare"

// Build cast-free accessors over your typed Env.
const { hyperdrive, r2, kv, queue } = makeCloudflare<Env>(() => env)

// In a handler:
const { connectionString } = yield* hyperdrive((e) => e.HYPERDRIVE)
```

### `@repo/db`
Drizzle ORM schema, the `Database` service tag, the request-scoped `connect`
factory, and reusable Effect query programs.

```typescript
import { UserQueries } from "@repo/db/queries"

// The request supplies the Database service.
const rows = yield* UserQueries.findAllUsers
```

## Applications

### `api`
REST HTTP API built with `effect/http-api` and served by `@repo/cloudflare`.

```bash
cd apps/api
bun run dev        # Local dev server
bun run deploy     # Deploy to Cloudflare
```

**Endpoints:**
- `GET /api/health` - Health check
- `GET /api/users` - List users
- `GET /api/users/:id` - Get user by ID
- `POST /api/users` - Create user
- `GET /api/openapi.json` - OpenAPI document

### `@repo/cli`

Bun CLI for API health and user management. Commands validate arguments with
the domain schemas and call the API through the shared HTTP contract.
See the [CLI guide](apps/cli/README.md) for commands and tests.

### `mcp`

Standalone MCP Worker with schema-validated tools backed by the shared HTTP
contract. See the [MCP guide](apps/mcp/README.md) for local setup and tests.

### `react-app`
The React SPA and Effect RPC Worker share one origin. `worker/index.ts` selects
the live database layer and `worker/runtime.ts` builds the router and RPC
server once per isolate. Each decoded user procedure opens its own scoped
connection and runs a query from `@repo/db/queries`. React calls the shared
`UsersRpc` contract at `/rpc` through the typed client in `src/atoms/`.

```bash
cd apps/react-app
bun run dev        # SPA + RPC worker on one dev server (port 3001)
bun test           # RPC routing and database scope tests
bun run deploy     # Build + deploy to Cloudflare
```

Use the [local Postgres setup](packages/db/README.md#change-the-schema) to run
the SPA with Hyperdrive. Both `POST /rpc` and `POST /rpc/` serve `UsersRpc`.

Reusable React controls and design tokens live in `packages/ui`. Import
`Button` from `@repo/ui/button` and labeled inputs from `@repo/ui/text-field`.
The app loads the UI SDK stylesheet and the shared theme in `src/styles.css`.
See [AGENTS.md](AGENTS.md) for the version-matched UI SDK docs.

## Core Patterns

### Effectful bindings
Cloudflare bindings are accessed through `@repo/cloudflare`. `makeCloudflare`
returns cast-free accessors backed by `CloudflareEnv`, a `Context.Reference`
that defaults to the `cloudflare:workers` env — so reading a binding adds
nothing to a handler's requirement channel:

```typescript
const { hyperdrive, r2, kv } = makeCloudflare<Env>(() => env)

Effect.gen(function* () {
  const { connectionString } = yield* hyperdrive((e) => e.HYPERDRIVE)
  // ...
})
```

### REST Worker lifecycle
`Worker.make` builds the API group layers and router once per isolate. It supplies
a fresh scope and Cloudflare execution context for each request.

The API's composition root passes a database layer to the users group.
Each users handler provides that layer after decoding the request. The layer
reads the Hyperdrive binding, opens the connection, and releases it when the
handler finishes. Health and OpenAPI require no database connection.

### Error Handling
Typed errors with automatic HTTP status mapping via `httpApiStatus`:

```typescript
export class UserNotFoundError extends S.TaggedError<UserNotFoundError>()(
  "UserNotFoundError",
  { id: S.Number, message: S.String },
  { httpApiStatus: 404 }
) {}
```

## Configuration

### TypeScript
Strict mode enabled with path aliases for all packages:

```json
{
  "compilerOptions": {
    "paths": {
      "@repo/domain": ["./packages/domain/src"],
      "@repo/contracts": ["./packages/contracts/src"],
      "@repo/cloudflare": ["./packages/cloudflare/src"],
      "@repo/db": ["./packages/db/src"]
    }
  }
}
```

### Cloudflare Bindings
Configure in `wrangler.jsonc`:

```jsonc
{
  "kv_namespaces": [{ "binding": "MY_KV", "id": "xxx" }],
  "r2_buckets": [{ "binding": "MY_R2", "bucket_name": "xxx" }],
  "hyperdrive": [{ "binding": "HYPERDRIVE", "id": "xxx" }]
}
```

### Hyperdrive (Database Connection Pooling)

Cloudflare Hyperdrive provides connection pooling for PostgreSQL. In production, configure via `wrangler.jsonc`:

```jsonc
{
  "hyperdrive": [{ "binding": "HYPERDRIVE", "id": "your-hyperdrive-id" }]
}
```

For **local development**, Wrangler simulates Hyperdrive using an environment variable. Create a `.env` file or export:

```bash
# .dev.vars (or export in shell)
CLOUDFLARE_HYPERDRIVE_LOCAL_CONNECTION_STRING_HYPERDRIVE="postgres://postgres:postgres@localhost:5432/effect_worker"
```

The `HYPERDRIVE` suffix must match your binding name. Wrangler will automatically provide `env.HYPERDRIVE.connectionString` in your worker.

## Key Dependencies

- **effect** (`4.1.5`) - Core runtime; HTTP and RPC live under `effect/http`, `effect/http-api`, and `effect/rpc`
- **@effect/sql-pg** (`4.1.5`) - Request-scoped PostgreSQL client
- **@effect/atom-react** - Reactive state for the React SPA
- **drizzle-orm** (`0.45.4`) and **drizzle-kit** (`0.31.11`) - Table definitions and migrations
- **@tanstack/react-router** - Type-safe file-based routing
- **wrangler** - Cloudflare Workers CLI

## Development Workflow

1. **Make changes** to packages or apps
2. **Build the workspace** to compile packages and generate the React route tree: `bun run build`
3. **Type check**: `bun run check`
4. **Run tests**: Start Docker and run `bun test`
5. **Dev server**: `cd apps/api && bun run dev`
6. **Deploy**: `bun run deploy`
